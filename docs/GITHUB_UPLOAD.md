# Publish the clean new-run repository and data

For a **new repository**, put the contents of `repository/` at its root and commit them with Git. Adjust the repository URL in `CITATION.cff` and README if you choose a different name. For the **existing** `mjavani54/nanophotonic-response-manifold-learning-resources` repository, the package's `replace_existing.sh` applies this fresh tree to a clean clone at its pinned main commit; it removes all old tracked main-branch files and leaves prior tags/releases untouched. Inspect `git status` and `git diff`, then commit and push with your own credentials.

The large binary arrays are **not Git-tracked**. Download all ZIP parts and run `python scripts/restore_data.py PARTS_DIRECTORY OUTPUT_DIRECTORY`. Verify the combined ZIP and every asset with `python scripts/verify_package.py --data OUTPUT_DIRECTORY/JMO_Data_Assets`. Upload the numbered data parts as binary assets of a **new draft release**, then download them anonymously and test restoration again before publishing the release. Record the actual release tag, URL, and date in the article and SI. Do not reuse or edit the earlier v1.1.0 tag, whose response model is different.

With an authenticated GitHub CLI and a tag chosen by the author, enter the extracted `repository/` directory, set `DATA_PARTS_DIR="/absolute/path/to/downloaded_parts"`, and run `gh release create YOUR_NEW_TAG "$DATA_PARTS_DIR"/JMO_New_Run_Data_part_*.zip --repo mjavani54/nanophotonic-response-manifold-learning-resources --draft --title "JMO present-study data" --notes-file RELEASE_NOTES_DRAFT.md`. If using a new repository name, change `--repo`. Review the release and run the anonymous download test before publishing it. If a bulk upload fails, retry individual numbered assets and verify the final asset count and hashes; do not publish a partial release.

The new primary and 200k ZIPs are reconstructed: their original whole-ZIP hashes recorded in the fit metadata differ. Three augmented NPZs are byte-identical, six known primary CSV members are byte-identical, and four spectral PCA diagnostics agree. Document these distinctions rather than asserting that every new array was byte-verified against a missing original archive. If the author's original two generated ZIPs can be supplied later, compare their member hashes and replace the reconstructed files only after a full identity check.
